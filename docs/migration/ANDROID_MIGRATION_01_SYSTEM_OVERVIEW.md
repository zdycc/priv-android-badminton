# 系统总览（原 badmintonding）

## 1. 原系统定位

原项目是“浙工大场馆预约助手”，由三层组成：

- 核心引擎：`main.py`（Python + Playwright）
- 控制服务：`ui_server.py`（本地 HTTP API）
- 展示层：`web/index.html + web/app.js`（网页向导）

迁移为纯 Android 后，建议保留“核心业务规则”，重写“执行层与界面层”。

## 2. 原系统核心能力

1. 首次登录并保存登录态
2. 配置预约参数（校区、场地号、时段、目标日期）
3. 计算开放时间（北京时间 07:00:05）
4. 到点执行预约
5. 失败后按规则重试（每分钟）
6. 成功/失败反馈与调试信息输出

## 3. 业务规则（必须保留）

### 校区规则

- `屏峰校区`
  - 场地号范围：`1~6`
  - 可选时段：`08:00-09:00, 09:00-10:00, 12:00-13:00, 17:00-18:00`

- `莫干山校区`
  - 场地号范围：`1~9`
  - 可选时段：`08:00-09:00 ... 20:00-21:00`（13 个）

### 日期规则

- `target_day_offset` 仅允许：`0(今天) / 1(明天) / 2(后天)`
- 开放时间规则：
  - 预约今天/明天：当日 `07:00:05`（北京时间）
  - 预约后天：明日 `07:00:05`（北京时间）

### 失败重试规则

- 不重试：
  - 时间段已被占用
  - 登录失败/登录态失效
- 重试：
  - 其他失败（系统繁忙、网络异常、未知异常等）
  - 重试间隔：每分钟

## 4. 原系统状态机（建议 Android 直接复刻）

可复用状态：

- `idle`
- `login`
- `ready`
- `waiting_open`
- `retrying`
- `success`
- `blocked`
- `stopped`

说明：

- `blocked` 表示“不可重试失败”
- `retrying` 表示“可重试失败并已进入倒计时重试”

## 5. 迁移后建议架构（纯移动端）

采用 Android 分层：

- `ui`：Compose/XML 页面
- `domain`：预约用例、状态机、规则
- `data`：接口调用、登录态存储、日志存储
- `crypto`：加密/签名模块（关键）

关键对象建议：

- `BookingConfig`
- `BookingOutcome`
- `BookingState`
- `RetryPolicy`
- `BookingScheduler`
- `BookingRepository`

## 6. 不迁移项（原项目特有）

- Playwright 页面选择器点击细节
- `web/` 页面样式和交互表现
- `ui_server.py` 的本地 HTTP 服务形态

这些在 Android 中由“原生请求 + 原生 UI + ViewModel 状态流”替代。
