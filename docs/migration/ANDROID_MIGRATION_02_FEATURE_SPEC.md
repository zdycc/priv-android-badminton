# 功能规格说明（Android 纯移动端）

## 1. 用户侧功能清单

### F1 登录管理

- 用户可触发登录流程
- 登录成功后本地持久化登录态
- 支持检测登录态是否有效
- 登录态失效时引导重新登录

验收标准：

- 首次登录后可连续执行预约，不要求每次重复登录

### F2 预约参数配置

- 选择校区（屏峰/莫干山）
- 选择日期（今天/明天/后天）
- 输入场地号（按校区范围校验）
- 选择时段（最多 2 个）

验收标准：

- 不允许非法参数进入“提交预约”流程

### F3 等待开放与自动触发

- 根据日期偏移自动计算开放时间（北京时间 07:00:05）
- 开放前显示倒计时
- 到点自动触发预约流程

验收标准：

- 倒计时结束后自动开始，无需人工点击

### F4 预约执行与结果判定

- 执行预约提交
- 判断成功信号（接口返回/关键页面信号等）
- 输出成功结果

验收标准：

- 成功状态必须可追踪并可展示关键信息（校区、日期、时段、场地）

### F5 失败分类与重试

- 对失败进行分类：可重试 / 不可重试
- 可重试失败每分钟自动重试
- 不可重试失败直接停止并提示

验收标准：

- 符合原策略：  
  - “时间段占用”不重试  
  - “登录失败”不重试  
  - 其他默认可重试

### F6 运行状态可视化

- 显示当前阶段（waiting_open/retrying/success/blocked 等）
- 显示失败原因与下一次重试时间
- 支持手动停止任务

验收标准：

- 用户始终知道“系统现在在干什么”

## 2. 业务规则约束

### R1 校区与场地限制

- 屏峰：`1~6`
- 莫干山：`1~9`

### R2 时间段选择限制

- 至少 1 个，最多 2 个
- 必须属于当前校区允许时段

### R3 日期选择限制

- 只允许今天/明天/后天
- 不允许任意日历日期

### R4 重试规则

- 间隔固定 60 秒
- 到达成功或不可重试错误则终止

## 3. 异常分类建议（Android 统一错误码）

- `LOGIN_INVALID`
- `SLOT_OCCUPIED`
- `SYSTEM_BUSY`
- `NETWORK_ERROR`
- `PAYLOAD_INVALID`
- `SUBMIT_FAILED_UNKNOWN`

并保留原始 message 作为 debug 文本。

## 4. 最小可用版本（MVP）

第一阶段必须实现：

1. 登录态持久化
2. 参数配置（校区/日期/场地/时段）
3. 开放时间倒计时
4. 自动预约与重试
5. 结果展示

可延后：

- 高级调试导出（类似 `debug/*.json`）
- 可视化统计
- 多任务并发预约

## 5. 验收用例（建议）

1. 有效登录态 + 合法参数 + 到点可预约 => 成功
2. 登录态失效 => `LOGIN_INVALID` 且停止重试
3. 时间段被占用 => `SLOT_OCCUPIED` 且停止重试
4. 系统繁忙 => 自动重试，直到成功或手动停止
5. 用户手动停止 => 状态变 `stopped`
